# Feature status

Only the subsets below have implementation evidence. This is **not** a blanket completion claim for the mockup or the full PRD.

| Area | Status | Evidence / boundary |
|---|---|---|
| Local decks and source | Implemented subset | Create/open/relink/hide, atomic local saves, source diagnostics, parent/child navigation and insertion, and source-preserving edits have unit/integration coverage. The default catalog and new decks live in home `.slides`; a copy-first legacy import retains the repository folder as a backup. An editable feature-tour deck is installed on demand without replacing edits. Files remain local. |
| Development mode | Implemented subset | Source/split/preview views, collapsible adjacent slide sections in outline and preview, direct plain-paragraph preview edits, per-slide section/metadata controls, grouped master controls, and 21 grouped layout/content samples are wired; structural/rich edits use source. Browser coverage exercises persisted options, gallery navigation, and representative rendered samples. |
| Content | Implemented subset | Basic Markdown, styled tables, syntax-highlighted code, KaTeX, constrained Mermaid, bounded inline JSON charts (line/bar/area/scatter/pie/donut), eight layouts including full-height left/right title images and a full-bleed image, four themes, reveal steps, and notes. One bundled example image is installed into the home library and available by exact reference in editor/presenter/audience; all other Markdown images display an unavailable-image fallback. General local assets and broader diagram syntax are not implemented. |
| Presentation mode | Implemented subset | Frozen saved deck, navigation and reveals, private notes/timer, pointer, ink, blank/blackout, explicit ink-discard confirmation, and local audience view. Browser coverage exercises reveals, navigation, blackout, ending, and notes privacy; annotation persistence/export is not implemented. |
| Audience/LAN | Implemented subset | Read-only audience route, sanitized shared rendering, reconnect, explicit interface/port sharing, and backend isolation tests. Remote-device connectivity and visual fidelity are not verified. |
| Integrated development | Implemented subset | `bun run dev` runs the Astro live-reloading UI and hot-reloaded Bun API together; the UI displays a DEV MODE badge. Backend reloads invalidate the owner token and active sessions, so save drafts and refresh after API source changes. LAN audience assets still require a production build. |
| Export | Deferred | Editor and presenter menus show disabled PDF and HTML options; no export functionality. |
| Custom components and authored code | Deferred | JSX/imports/expressions, component registration, and execution are intentionally unavailable. |
| Full acceptance | Unverified | Browser end-to-end coverage exists for selected flows, not full mockup/PRD parity, accessibility/security review, physical LAN sharing, or measured performance. |

Current validation: `bun run check` (0 errors, 0 warnings, 13 hints), `bun test ./tests` (45 passing), `bun run build`, and `bunx playwright test` (14 Chromium tests passing). The existing repository deck was verified byte-identical to the imported home copy, with a usable home catalog and the original untouched; the bundled illustration was verified byte-identical in the home assets folder. A prior loopback host smoke check returned 200 for `/`, `/audience/`, and `/api/bootstrap`; owner-protected `/api/library` rejected an unauthenticated request with 403 and accepted an authenticated request with 200. Browser tests exercise section groups, per-slide metadata parity in presenter/audience, full-height images, a visible and in-frame Mermaid sample, table styling, a reusable demo deck, persisted source, the fixed image route and unknown-image fallback, local audience updates, export controls, and external-edit conflict; they do not prove remote-device LAN behavior, security certification, accessibility, or performance thresholds.
