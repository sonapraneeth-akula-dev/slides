# Feature status

Only the subsets below have implementation evidence. This is **not** a blanket completion claim for the mockup or the full PRD.

| Area | Status | Evidence / boundary |
|---|---|---|
| Local decks and source | Implemented subset | Create/open/relink/hide, atomic local saves, source diagnostics, parent/child navigation and insertion, and source-preserving edits have unit/integration coverage. Personal decks live in home `Presentations`; the catalog, assets, and tours stay in `.slides`, with tours under `feature-tours`. Older app-root decks migrate without overwriting conflicts or external files. One tour action reopens the current bundled edition, refreshes unchanged older copies in place, and removes provably unchanged redundant tours while preserving edited ones. Files remain local. |
| Development mode | Implemented subset | Source/split/preview views, collapsible adjacent slide sections in outline and preview, direct plain-paragraph preview edits, per-slide section/metadata controls, grouped master controls with numeric dropdowns and an opt-in installed-font picker, and 21 grouped layout/content samples are wired; structural/rich edits use source. Browser coverage exercises persisted options, gallery navigation, font-permission fallbacks, responsive home layout, and representative rendered samples. |
| Content | Implemented subset | Basic Markdown, styled tables, syntax-highlighted code, KaTeX, constrained Mermaid, bounded inline JSON charts (line/bar/area/scatter/pie/donut), eight layouts including full-height left/right title images and a full-bleed image, four themes, reveal steps, and notes. Mermaid diagrams use the same responsive stage sizing in draft preview, master samples, presenter, and audience. One bundled example image is installed into the home library and available by exact reference in editor/presenter/audience; all other Markdown images display an unavailable-image fallback. General local assets and broader diagram syntax are not implemented. |
| Presentation mode | Implemented subset | Frozen saved deck, navigation and reveals, private notes/timer, pointer, ink, blank/blackout, explicit ink-discard confirmation, and local audience view. Browser coverage exercises reveals, navigation, blackout, ending, and notes privacy; annotation persistence/export is not implemented. |
| Audience/LAN | Implemented subset | Read-only audience route, sanitized shared rendering, reconnect, explicit interface/port sharing, and backend isolation tests. Remote-device connectivity and visual fidelity are not verified. |
| Integrated development | Implemented subset | `bun run dev` runs the Astro live-reloading UI and hot-reloaded Bun API together; the UI displays a DEV MODE badge. Backend reloads rotate the owner token and end active sessions. Owner requests refresh the token once; End returns to the editor if the previous session no longer exists. Save drafts and restart the presentation after a backend reload. LAN audience assets still require a production build. |
| Export | Deferred | Editor and presenter menus show disabled PDF and HTML options; no export functionality. |
| Custom components and authored code | Deferred | JSX/imports/expressions, component registration, and execution are intentionally unavailable. |
| Full acceptance | Unverified | Browser end-to-end coverage exists for selected flows, not full mockup/PRD parity, accessibility/security review, physical LAN sharing, or measured performance. |

Current validation: `bun run check` (0 errors, 0 warnings, 17 hints), `bun test ./tests` (50 passing), `bun run build`, and `bunx playwright test` (19 Chromium tests passing). The existing repository deck was verified byte-identical to the imported home copy, with a usable home catalog and the original untouched; the bundled illustration was verified byte-identical in the home assets folder. A prior loopback host smoke check returned 200 for `/`, `/audience/`, and `/api/bootstrap`; owner-protected `/api/library` rejected an unauthenticated request with 403 and accepted an authenticated request with 200. Browser tests exercise responsive home layout, installed-font selections and permission failures, numeric dropdowns and preserved fractional settings, separated presentation/tour library groups, section groups, per-slide metadata parity in presenter/audience, full-height images, a Mermaid diagram that clears the footer at multiple slide widths, chart data hidden visually but kept in an accessible table, grouped presenter controls at three widths, notes on all 16 demo slides, installation of a fresh demo without overwriting edits, CRLF presentation and saves, persisted source, the fixed image route and unknown-image fallback, local audience updates, expired-token recovery when ending a presentation, export controls, and external-edit conflict; they do not prove remote-device LAN behavior, security certification, accessibility, or performance thresholds.
